# Install host files

The installer supplies three agent definitions and two configuration seeds. Existing user configuration remains user-owned. Verification installs only into a disposable home.

## Sub-features

- Dry-run reports intended actions without writing files.
- First apply creates five files with generated bytes.
- Repeated apply leaves bytes and modes unchanged.
- Modified configuration seeds remain unchanged.
- A conflicting agent fails before any file is written.

## How to get to it (user POV)

The public entry is `node scripts/install.mjs`. Its explicit options are `--home`, `--generated-root` and `--apply`. The default home is real user state. Never use that default for a portable test.

## Driving it with verify-pi-pstack

Preconditions: doctor passes. Run `npm run verify`.

Read the `installer-dry-run` log for the actual command and reported actions. Require `dry-run-no-writes` to pass. Require first apply to succeed and `installer-five-files` to confirm three agents and two seeds. Require repeat identity and custom preservation checks to pass. The `npm-test` log includes the CLI conflict regression, which checks unchanged filesystem state after refusal.

The command records its actual disposable paths in the logs. Read `summary.json` and confirm the owned scratch home was removed while evidence remains.

## Gotchas

`--apply` is appropriate only with the explicitly allocated fixture home. Dry-run proof observes the fixture filesystem; the installer has no remote or browser path. This lane does not verify user-level skill symlink installation. `npm run test:installed` is a separate opt-in loader check after actual installation.
