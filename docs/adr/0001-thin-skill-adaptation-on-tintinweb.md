# 0001：以薄适配包接入 pstack，复用 Tintinweb，只做显式调用

日期为 2026-10-01。状态为已接受。

## 背景

用户要在 Pi 中使用上游 pstack 的主要工作流和技能内的流程引导。云端功能和 Cursor 专属功能不需要适配。

已有调查显示，社区 Pi 移植都不能原样使用。`pi-pstack@0.1.0` 依赖当前 Pi 命令上下文中不存在的 API，自带竞争的子代理 runner，且落后于上游 0.15.5。其他候选依赖 Nico 子代理系统或另一套角色协议。

本机已装的 Tintinweb 子代理系统提供 `model`、`thinking`、后台运行、续接、中途引导和 worktree 隔离。本机还已装 `ask_user_question`、pi-goal 和 pi-skillful。上游技能主要依赖的宿主能力已经齐备。

上游 Poteto Mode 的持续模式依赖 Cursor 每轮注入提醒。社区移植用 extension 模拟这一点，调查发现的问题多数出在这一层。

## 决定

1. 从固定的本机上游快照生成适配包，提交进本仓库。上游正文尽量保持原文。所有改动都是带锚点的声明式改动。
2. 不写 Pi extension，不安装社区 Pi 移植，不引入第二套子代理 runner。子代理统一通过 Tintinweb 子代理系统调用。
3. 只支持显式调用。不实现持续模式、每轮提醒或自动路由。
4. 上游的 Cursor 能力通过一份映射说明对应到 Pi。需要调用子代理的技能在开头指向这份说明。
5. 角色模型由用户级模型表决定。未写入的角色使用主模型。指定模型失败时执行回退规则。
6. 新增的 agent 文件不写 model 和 thinking，由技能在调用时指定。
7. 适配包替换用户共享技能目录中的上游 pstack 技能。之前安装的上游技能只是试用，不需要保留。

## 后果

- 适配成本集中在少量文本改动、三个 agent 文件、映射说明和重写的 setup-pstack。
- 上游更新时，重新运行生成即可。锚点失效会让生成失败，而不是静默漂移。
- 用户每个任务都要显式调用 poteto-mode。上下文压缩后要重新调用。
- 同一共享技能目录的其他工具也会读到适配包。用户已接受这一点。
- 云端子代理、Cursor 自动化和持续模式不提供。差异清单见对应 spec。
